Config can now travel from a node back to the hub. `cc-fleet push skill/<id>` offers something you authored in `~/.agents/local/` to the hub, where it waits in a pending inbox — `cc-fleet pending` lists offers, `cc-fleet adopt <device> <kind>/<id> --group <group>` makes one fleet config, `cc-fleet reject` discards it. Adoption is always a human act: nothing a node sends becomes fleet config by itself. Nodes also report an inventory of what they hold locally — **ids only, never content** — so the hub can show unadopted work without collecting it.
